# 第一阶段需求

## 当前状态

规划中

本文件定义第一阶段的拟定产品边界。只有项目作者确认后，它才成为正式的第一阶段需求。

## 目标

建立初步的模型 API 调用能力，并通过实际工程实践理解小型 LLM Agent 背后的控制模型。

本阶段应完成一个最小但完整的受控闭环，而不是建设功能繁多的通用 Agent 平台。

## 用户可观察流程

第一阶段应支持以下可观察流程：

```text
用户输入
  → Agent Runtime
  → 模型请求
  → 直接回答或结构化工具请求
  → 工具校验与执行
  → 工具结果返回模型
  → 最终回答、另一个受限步骤或受控终止
```

除非后续形成新的确认决定，第一种交互方式采用同步 CLI。

## 必须具备的行为

### 模型交互

- 系统能够将用户请求发送给模型。
- 系统能够处理模型直接返回的回答。
- 系统能够处理模型对已注册工具的请求。
- 系统能够将工具结果返回给模型。
- 系统能够处理模型后续回答，或以明确原因终止运行。

### Runtime 控制

- Runtime 负责执行循环。
- 模型不能直接执行代码、Shell 命令或未注册能力。
- Runtime 强制执行最大运行步数。
- Runtime 强制执行工具调用次数上限。
- Runtime 能区分正常完成、模型失败、工具失败、非法请求、达到上限和用户取消。
- 发生异常时，运行不能停留在没有明确最终状态的情况。

### 工具边界

第一批工具应保持少量且低风险：

- `calculate`：使用明确操作名和数值参数执行确定性计算，不使用 `eval`。
- `list_workspace_files`：只列出明确配置的工作目录中的有限条目，校验路径解析结果，防止越界访问工作目录之外的内容。

文件写入、任意 Shell 执行、产生网络侧影响的操作和高风险系统修改不属于本阶段。

### Trace 与可观察性

每次运行都应具有 Run ID。Trace 至少记录：

- 运行和步骤标识；
- 事件类型；
- 诊断所需的模型和工具调用元数据；
- 执行耗时；
- 错误及其分类；
- 最终停止原因。

默认日志不得记录 API Key、密钥或不必要的敏感文件内容。

## 测试要求

Runtime 必须能够在不调用真实模型 API、也不依赖网络的情况下进行测试。

离线测试至少覆盖：

- 模型直接返回；
- 工具请求成功；
- 工具执行失败；
- 未知工具；
- 非法工具参数；
- 多次受限工具调用；
- 达到执行步数上限；
- 模型异常；
- 在选定的 CLI/Runtime 边界支持时验证用户取消；
- Trace 生成和最终停止原因。

真实模型调用用于接入和整体行为冒烟验证，不能替代确定性的 Runtime 测试。

## 安全和隐私边界

- 凭据必须来自本地环境或等价的安全配置机制。
- 凭据不得提交、打印或写入 Trace。
- 不得把模型生成的文本当作任意 Shell 命令执行。
- 本地文件系统工具必须使用明确且受限的工作目录。
- 工具返回内容必须限制规模。
- 未来任何修改系统状态、访问敏感数据或产生外部副作用的工具，都需要单独设计权限策略并取得作者确认。

## 延后能力

以下能力不属于第一阶段：

- Planning 系统；
- 持久化 Memory；
- Reflection Loop；
- RAG；
- MCP；
- 多 Agent 协作；
- 后台并发；
- 持久化任务和任务恢复；
- 通用 HTTP 服务基础设施；
- Android 集成；
- 任意 Shell 或不受限制的文件系统操作。

引入其中任何能力，都需要说明具体问题、与简单替代方案的比较、验收标准和明确决策。

## 验收标准

满足以下条件后，第一阶段可以进入评审：

1. 本地 CLI 能接受请求，并产生最终回答或受控终止。
2. 模拟模型能够在不联网、不使用凭据的情况下验证 Runtime Loop。
3. 已注册工具能够被校验、执行，并将结果返回模型。
4. 执行步数和工具调用上限能够阻止失控循环。
5. 模型失败、工具失败、非法请求、取消和达到上限能够产生可区分的结果。
6. 结构化 Trace 能解释一次运行的重要事件，且默认不暴露密钥。
7. 自动化测试覆盖要求中的 Runtime 行为。
8. 已完成一次真实模型冒烟验证，并将其结果与离线测试证据分开记录。
9. 项目作者能够解释模型、Runtime、工具注册表、工具实现和 Trace 各自的职责。
