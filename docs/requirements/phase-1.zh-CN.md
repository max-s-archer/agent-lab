# 第一阶段需求

## 当前状态

已确认，适用于最初的 API 调用切片。

本文件是第一阶段的权威需求。它只定义直接模型调用切片，并不授权在作者另行批准前创建工程配置或实现代码。

## 目标

建立 CLI 到阿里云百炼的一次正确同步调用，并理解请求与返回结果之间的边界。

本阶段将用户输入直接发送到模型 API 并处理返回结果。它不加入工具、Planning、Memory、文件操作或其他中间 Agent 行为。

## 用户可观察流程

第一阶段应支持以下可观察流程：

```text
CLI 输入
  → 直接请求百炼
  → 返回结果处理
  → CLI 输出或受控错误
```

交互方式为同步。模型提供商是阿里云百炼，使用其 OpenAI 兼容接口。Runtime 不得直接依赖提供商 SDK。

## 必须具备的行为

### 模型交互

- CLI 接受一次用户输入，并将其直接发送给已配置的模型。
- 系统处理成功返回的文本并显示它。
- 系统以受控消息报告配置错误、传输错误和返回格式错误。
- 本阶段不调用工具，也不发起下一轮模型请求。

### 技术基线

- Python 3.12。
- 使用 `uv` 和 `pyproject.toml`。
- 包布局为 `src/agent_lab/`。
- 使用 `pytest` 测试，使用 Ruff 做代码检查。
- 凭据从环境变量读取，绝不写入源码或日志。

## 测试要求

Runtime 必须能够在不调用真实模型 API、也不依赖网络的情况下进行测试。

离线测试应覆盖：

- 根据 CLI 输入构造请求；
- 成功返回结果的处理；
- 缺少配置；
- 传输或提供商失败；
- 提供商返回格式异常；
- 日志中不存在凭据、不必要的提示内容或敏感返回内容。

真实模型调用用于接入和整体行为冒烟验证，不能替代确定性的 Runtime 测试。

## 安全和隐私边界

- 凭据必须来自本地环境或等价的安全配置机制。
- 凭据不得提交、打印或写入 Trace。
- 不得把模型生成的文本当作任意 Shell 命令执行。
- 本地文件系统工具必须使用明确且受限的工作目录。
- 工具返回内容必须限制规模。
- 未来任何修改系统状态、访问敏感数据或产生外部副作用的工具，都需要单独设计权限策略并取得作者确认。

## 延后能力

以下能力不属于第一阶段：

- 工具调用和多步骤 Agent Loop；
- Planning 系统；
- 持久化 Memory；
- Reflection Loop；
- RAG；
- MCP；
- 多 Agent 协作；
- 后台并发；
- 持久化任务和任务恢复；
- 通用 HTTP 服务基础设施；
- Android 集成；
- 任意 Shell 或不受限制的文件系统操作。

引入其中任何能力，都需要说明具体问题、与简单替代方案的比较、验收标准和明确决策。

## 验收标准

满足以下条件后，第一阶段可以进入评审：

1. 本地 CLI 将一次输入直接发送到已配置的模型边界。
2. 成功返回的文本被直接显示，中间不进行工具处理。
3. 缺少配置、传输失败和返回格式异常会以可区分的消息终止。
4. 自动化测试在不访问网络的情况下验证请求构造和返回处理。
5. 源码、示例和日志中不存在凭据。
6. 一次真实百炼冒烟调用与离线测试证据分开记录。
7. 项目作者能够解释 CLI、提供商适配层、请求和返回结果各自的职责。
