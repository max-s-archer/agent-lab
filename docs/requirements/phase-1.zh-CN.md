# 第一阶段需求

## 当前状态

已确认，适用于受控 Runtime 切片。

本文件是第一阶段的权威需求。Runtime 切片使用模拟模型进行测试。新的真实百炼调用仍需单独授权。

## 目标

建立 CLI 到阿里云百炼的一次正确同步调用，并理解请求与返回结果之间的边界。

本阶段保留直接模型调用，并增加一个受控决策点。模型可以直接回答，也可以请求确定性的 `calculate` 工具。Runtime 校验并执行该请求，再将工具结果返回模型。它不加入文件操作、Planning、Memory 或其他工具。

## 用户可观察流程

第一阶段应支持以下可观察流程：

```text
CLI 输入
  → 模型决策
  → 可选的 calculate 校验与执行
  → 工具结果返回模型
  → 最终回答或受控停止
```

交互方式为同步。模型提供商是阿里云百炼，使用其 OpenAI 兼容接口。Runtime 不得直接依赖提供商 SDK。

## 必须具备的行为

### 模型交互

- CLI 接受一次用户输入并启动一次 Runtime。
- 模型可以直接返回文本。
- 模型可以一次请求 `calculate`，并提供明确操作和数值参数。
- Runtime 在执行前校验工具名和参数。
- 工具结果返回模型后，模型必须给出最终文本。
- Runtime 最多允许两次模型调用和一次工具调用。
- 未知工具、非法参数、模型失败和步数上限会以可区分的消息停止。

### 技术基线

- Python 3.12。
- 使用 `uv` 和 `pyproject.toml`。
- 包布局为 `src/agent_lab/`。
- 使用 `pytest` 测试，使用 Ruff 做代码检查。
- 凭据从 `DASHSCOPE_API_KEY` 环境变量读取，绝不写入源码、示例或日志。
- 初始模型为 `qwen3.8-flash`。
- OpenAI 兼容接口地址为 `https://ws-nnpvwzj2vhzbu3i6.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。
- 请求超时时间为 30 秒。

## 测试要求

Runtime 必须能够在不调用真实模型 API、也不依赖网络的情况下进行测试。

离线测试应覆盖：

- 直接回答；
- 成功计算并给出最终回答；
- 未知工具；
- 非法计算参数；
- 模型或传输失败；
- 两次模型调用上限；
- 提供商返回格式异常；
- 日志中不存在凭据、不必要的提示内容或敏感返回内容。

真实模型调用用于接入和整体行为冒烟验证，不能替代确定性的 Runtime 测试。

## 安全和隐私边界

- 凭据必须来自本地环境或等价的安全配置机制。
- 凭据不得提交、打印或写入 Trace。
- 不得把模型生成的文本当作任意 Shell 命令执行。
- 本地文件系统工具必须使用明确且受限的工作目录。
- 工具返回内容必须限制规模。
- 未来任何修改系统状态、访问敏感数据或产生外部副作用的工具，都需要单独设计权限策略并取得作者确认。

## 延后能力

以下能力不属于第一阶段：

- 超出单一 `calculate` 工具的工具调用；
- Planning 系统；
- 持久化 Memory；
- Reflection Loop；
- RAG；
- MCP；
- 多 Agent 协作；
- 后台并发；
- 持久化任务和任务恢复；
- 通用 HTTP 服务基础设施；
- Android 集成；
- 任意 Shell 或不受限制的文件系统操作。

引入其中任何能力，都需要说明具体问题、与简单替代方案的比较、验收标准和明确决策。

## 验收标准

满足以下条件后，第一阶段可以进入评审：

1. 模型直接回答时不执行工具。
2. 合法的 `calculate` 请求被执行，且结果返回模型。
3. 未知工具和非法参数不会执行工具。
4. Runtime 在两次模型调用时停止。
5. 自动化测试在不访问网络的情况下验证行为。
5. 源码、示例和日志中不存在凭据。
6. 一次真实百炼冒烟调用与离线测试证据分开记录。
7. 项目作者能够解释 CLI、提供商适配层、请求和返回结果各自的职责。
